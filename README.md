# Система мониторинга пользовательских заявок

Консольное приложение для регистрации, обработки и контроля пользовательских
заявок. В ПР3 проект переработан из функциональной модели в
объектно-ориентированную: данные предметной области представлены объектами,
а относящееся к ним поведение реализовано методами классов.

## Возможности

- просмотр заявок с сортировкой по приоритету и времени создания;
- поиск по теме заявки или имени пользователя;
- создание заявки с проверкой введённых данных;
- смена статуса и отмена заявки без удаления из истории;
- автоматическое выделение срочных заявок;
- вывод статистики по статусам;
- сохранение заявок и истории действий в JSON.

## Объектная модель

### User

Класс `User` представляет пользователя системы и хранит `id` и `name`.
Методы `to_data()` и `from_data()` преобразуют объект в JSON и обратно, а
`__str__()` возвращает имя пользователя.

### Request

Класс `Request` представляет пользовательскую заявку. Он хранит `id`, `title`,
ссылку `user` на объект `User`, `priority`, `status`, `created_at` и
`response_limit_hours`.

Основные методы:

- `needs_attention()` определяет необходимость реакции оператора;
- `change_status()` изменяет статус заявки;
- `cancel()` переводит открытую заявку в состояние «отменена»;
- `to_data()` и `from_data()` преобразуют объект в данные JSON и обратно;
- `__str__()` возвращает краткое строковое представление.

`validate_response_limit()` является статическим методом: он проверяет срок
реакции, не обращаясь к данным конкретного объекта.

### RequestEvent

Класс `RequestEvent` представляет событие истории. Он хранит `id`, `event_type`,
`comment`, `created_at` и ссылку `request` на объект `Request`. Объекты связаны
цепочкой `RequestEvent` → `Request` → `User`; в JSON сохраняются только их
идентификаторы.

## Структура проекта

```text
frame 5/
├── main.py              # консольное меню и пользовательские сценарии
├── requests.py          # класс Request и операции с коллекцией заявок
├── users.py             # класс User и создание пользователей
├── events.py            # класс RequestEvent и история заявок
├── monitoring.py        # сводная статистика и сообщения оператору
├── storage.py           # JSON ↔ объекты Request и RequestEvent
├── utils.py             # безопасный ввод данных
├── data/
│   ├── requests.json    # данные заявок
│   ├── events.json      # данные истории событий
│   └── users.json       # данные пользователей
└── tests/
    ├── test_requests.py
    └── test_monitoring.py
```

## Хранение данных

При запуске `load_users()` создаёт объекты `User`, `load_requests()` связывает
с ними объекты `Request`, а `load_events()` связывает историю с заявками.
Перед сохранением методы `to_data()` превращают объекты обратно в словари,
поэтому формат JSON остаётся простым и переносимым.

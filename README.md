# Система мониторинга пользовательских заявок

> Проект по контролю статусов, приоритета и срока реакции на пользовательские заявки.

## Назначение

Приложение помогает контролировать обработку пользовательских заявок: определять, требуется ли срочная реакция, и показывать текущий статус заявки.

## Целевая аудитория

Сотрудники службы поддержки, операторы и руководители, которые принимают и контролируют пользовательские заявки.

## Предметная область

Пользователь создаёт заявку, а сотрудники отслеживают её статус, приоритет и события обработки. Система должна помогать не пропускать заявки, для которых истекает допустимое время ответа.

## Основные сущности

- Пользователь
- Заявка
- Событие заявки
- Статус заявки

## Основные функции

- Регистрация и просмотр пользовательских заявок
- Изменение статуса и приоритета заявки
- Фиксация событий обработки
- Контроль срока первого ответа и выделение срочных заявок

## Начальный сценарий ПР1

`main.py` принимает номер заявки, её статус, приоритет и количество часов с момента создания. Программа определяет, нужна ли срочная реакция, и выводит понятное сообщение оператору. В сценарии используются простые типы данных, преобразование типов, операции, ветвления и импорт модуля `datetime`.

## Функции

В проекте определены и вызываются три пользовательские функции:

1. `print_request_information(request_id, status, created_at)` - выводит номер, статус и время создания заявки.
2. `determine_action(status, is_high_priority, is_overdue)` - определяет, требуется ли оператору срочная реакция.
3. `print_action(action)` - выводит итоговое сообщение для оператора.

## Запуск

```bash
python main.py
```

После запуска программа запросит номер заявки, статус (`new`, `in_progress` или `closed`), приоритет (`high` или `normal`) и число часов с момента создания.

## Отладка

Для отладки в IDE установьте точку останова на строке с условием `if status == "closed":`, запустите файл в режиме Debug и проверьте значения переменных. Затем для учебного поиска ошибки временно замените условие `hours_since_creation >= response_limit_hours` на `hours_since_creation <= response_limit_hours`: заявка, созданная недавно, ошибочно станет срочной. После обнаружения ошибки верните оператор `>=`.
